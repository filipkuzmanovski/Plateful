# Frontend refresh ("Cookbook"): design

Date: 2026-11-02
Status: approved in conversation (sections 1 and 2 shown; the user approved the rest without seeing it:
"I trust you completely on the frontend ... I approve them all"). This written spec is awaiting review.
Frontend only (`recipe-app-frontend/`). No backend changes.
Mockups of the chosen direction: private artifact "Plateful Directions", direction A.

## 1. Goal

Give Plateful a fresher, more distinctive look across every screen, add dark mode, and fix the
accessibility and phone problems found in the review. Keep what makes Plateful recognisable: the dark
olive, the saffron dot in the wordmark, the warm feel. Behaviour, routes, data and copy stay the same
except where this spec says otherwise.

## 2. Decisions from the conversation

| Question | Decision |
|---|---|
| Which screens | **All of them**, in one consistent pass. |
| Polish or new direction | **Evolve** Golden Hour: keep the olive, saffron dot and warmth; drop the parts that read as generic AI design (cream plus terracotta, the one-italic-word headline, the same card on everything, all-caps eyebrow labels). |
| Dark mode | **Build it now**: Match my device (default), Light, Dark. |
| Direction | **A. Cookbook**: book-paper page, olive ink, saffron only as a marker colour; Newsreader serif plus Hanken Grotesk; recipes sit on the page without boxes; Today's meals set like a printed menu; ingredients in a tinted panel and steps with large hanging numbers. |
| Token names | **Rename by role** (`page`, `ink`, ...) and update every component, so names stay true in dark mode. |
| Phone header | Logo, Cook, theme menu and avatar. New recipe, Review queue (admins), My profile and Sign out move into the avatar menu below `sm`. |

## 3. Review findings this fixes

Measured on `main` at `2ed40ba` (live at 1024px and 375px, signed out; signed-in screens by code).

- Small text below WCAG AA 4.5:1: `text-muted` #8a8a7a on cream 3.25; `text-olive/60` 3.51 (Today's meals
  "Generated by AI"); terracotta small text 3.88 (Today's meals labels). Secondary `text-olive/70` is 4.61.
- Over 50 uses of 10, 11 or 12px text. Content pages set long reading text at 14px / 20px.
- Inputs use 14px text, so iOS Safari zooms the page on focus.
- Recipe photos are 312x231 Spoonacular files, stretched on phones (blurry at 2x). No `srcset`.
- Today's meals cards have no photos and look weaker than the photo cards next to them.
- Every surface uses the same rounded paper card, shadow and ring.
- All-caps tracked labels in the filter drawer, sea cards and Today's meals.
- One recipe per row on phones (about 370px tall each).
- Signed-in nav at 375px: five items in one row.

### 4.2 Type

- `--font-serif`: **Newsreader Variable** (`@fontsource-variable/newsreader`, optical-size axis;
  import the `opsz` and `opsz-italic` files). Headings, the wordmark, recipe titles, step numbers,
  fact values, empty-state sentences.
- `--font-sans`: **Hanken Grotesk Variable** (`@fontsource-variable/hanken-grotesk`). Everything else.
- Remove `@fontsource-variable/fraunces` and `@fontsource-variable/inter`.
- Scale (px): 13, 15, 16, 18, 22, 28, 36, 48. Serif headings use weight 500 or 600, tracking -0.015em.
  - Page titles: 36, or 48 from `sm`.
  - Section headings: 22 or 28.
  - Card titles: 17 or 18.
  - Body: 16.
  - Secondary: 15 or 13.
- **Minimum 13px** for any text, except number badges (12px, bold, `tabular-nums`). Replace
  `text-[10px]`, `text-[11px]` and content uses of `text-xs` with `text-[13px]`.
- Long reading text (recipe steps and instructions, content pages, AI descriptions): 16px,
  `leading-relaxed` (1.625) or more, lines at most about 70 characters (`max-w-prose`).
- **No all-caps labels.** Sentence case, weight 600, `ink-soft`.
- No single accented word in a heading. Home hero becomes plain: "Find tonight's dinner".

### 4.3 Shape, depth and motion

- Radii:
  - Buttons and filter chips: fully rounded.
  - Photos and recipe-card images: 6px (`rounded-md`).
  - Inputs: 8px.
  - Panels, dialogs and menus: 12px (`--radius-card` becomes 0.75rem).
  - Non-interactive tags: 4px.
- Shadows only for things that float: menus, dialogs, the drawer, toasts (`--shadow-float`).
  `shadow-card`, `shadow-lift` and `shadow-button` are removed. Containers that stay use a 1px `rule`
  border instead.
- No hover lift or image zoom anywhere. Hover changes colour, underline or a slight photo darkening.
- Keep the existing dialog, drawer, sheet, menu and view keyframes. Keep the `prefers-reduced-motion`
  rule.
- Body background: flat `page`. The radial glow is removed.

## 5. Dark mode

- **`src/theme/theme.ts`**: the choice type (`'system' | 'light' | 'dark'`), and storage under
  localStorage `plateful.theme` with try/catch (a missing or unreadable value means `system`).
  `resolveTheme(choice, prefersDark)` returns the resolved mode, and `applyTheme(resolved)` sets
  `document.documentElement.dataset.theme` and `style.colorScheme`.
- **`src/theme/ThemeProvider.tsx`**: React context `{ choice, setChoice }`. It applies the theme on
  change. While the choice is `system` it listens to `matchMedia('(prefers-color-scheme: dark)')`
  changes. It also listens to the `storage` event so other tabs follow.
- **`index.html`**: a small inline script before the app reads the stored choice and the media query, and
  sets `data-theme` before first paint (no flash). Add `<meta name="color-scheme" content="light dark">`
  and `<meta name="theme-color">` for both schemes (`#fbfbf7`, `#161a14`).
- **`src/components/ThemeMenu.tsx`**: an icon button in the header (Sun, Moon or Monitor icon for the
  current resolved or chosen mode; accessible name "Theme: Match my device", "Theme: Light" or
  "Theme: Dark") with `aria-haspopup="menu"` and `aria-expanded`. The menu has three `menuitemradio`
  items with `aria-checked`: Match my device, Light, Dark. Arrow keys move between items, Enter or Space
  chooses, and Escape or an outside click closes and returns focus to the button.
- jsdom has no `matchMedia`; `src/test/setup.ts` gets a default stub (`matches: false`) if one is not
  already defined. Tests that stub it themselves (ShareRecipe) keep working.
- Toaster, Radix dialogs and selects, the filter drawer and video and photo viewers take colours only
  from tokens, so they follow the mode. The video viewer's black backdrop stays black in both modes.

## 8. Photos

- **`src/lib/recipeImage.ts`**: `recipeImageSrcSet(url)`. For URLs on `img.spoonacular.com/recipes/` that
  end in `-{w}x{h}.{ext}`, it returns
  `srcSet = "{base}-312x231.{ext} 312w, {base}-480x360.{ext} 480w, {base}-636x393.{ext} 636w"`. Any
  other URL returns `undefined`. Supabase uploads are already up to 1536px, so they need no srcset.
- RecipeCard: `srcSet` plus `sizes="(min-width: 1024px) 270px, 50vw"`.
- PhotoCollage's main image: `sizes="(min-width: 1024px) 460px, 100vw"`.
- `object-cover` handles the 636x393 aspect.
- Photos keep `alt=""` where the title is next to them (as today).

## 9. Accessibility checklist (every task)

- No emojis. Screen tests keep `expectNoEmoji()`.
- Every text and background pair uses the tokens in section 4.1, in both modes. No literal colours.
- Existing ARIA tab patterns, live regions (`role="status"`, `role="alert"`), `aria-pressed`,
  `aria-expanded`, `aria-current` and keyboard handling are unchanged.
- Touch targets: buttons 44px; icon buttons, chips, pagination and reactions at least 40px.
- Focus visible on everything; no `outline-none` without a replacement ring.
- `prefers-reduced-motion` still respected.
- No horizontal scroll at 375px.
