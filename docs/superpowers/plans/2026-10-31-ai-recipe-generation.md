# AI Recipe Generation and Daily Meals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Signed-in users generate new, private recipes from the ingredients they have, and get three AI-generated daily meals once per local day. Both are grounded in the RecipeNLG reference data and checked in code for safety and novelty.

**Architecture:**
- **Provider transport:** package `ai`. A `RecipeAi` interface with Groq and Gemini implementations over `RestClient`, and a `FallbackRecipeAi` that tries them in `plateful.ai.order`.
- **Recipe logic:** package `generation`. Reference finding, prompts, parsing, the safety and novelty checks, the feature-1 and daily-meals services, the usage counter and the cleanup job.
- **Storage:** three new Flyway V9 tables, read and written with JPA (`generated_recipes`) and `NamedParameterJdbcTemplate` (the atomic claim and counter statements).
- **Frontend:** a `features/ai` folder: `/cook`, `/ai-recipes/:id`, the home "Today's meals" strip, a fourth profile tab and a Privacy paragraph.

**Tech Stack:** Spring Boot 4 / Java 21 / Hibernate 7 / Flyway / `RestClient` / `MockRestServiceServer` / `NamedParameterJdbcTemplate`; React 19 / TypeScript / TanStack Query / Vitest / MSW.

**Spec:** `docs/superpowers/specs/2026-10-31-ai-recipe-generation-design.md` (read it with this plan; section numbers below are the spec's).

## Rulings made while planning (spec clarifications)

1. **Free-text matching** uses a new `IngredientNames.normaliseWords(String) -> String`, the Java twin of Python's `normalise_words` (singularise every word, no length limit, never null). `FoodRules.allergensInText` and `dietViolationsInText` pad its result and run the existing group matcher. The dislike check on text uses the same normalised text.
2. **`generated_recipes.recipe` and `request`** are mapped as `Map<String, Object>` with `@JdbcTypeCode(SqlTypes.JSON)`, as `Recipe.nutrition` already is. The service converts with Jackson to and from the `StoredRecipe` and request records.
3. **`daily_meal_sets` and `ai_usage` have no entities.** Their statements (claim, take-over, finish, reserve, refund) need `ON CONFLICT ... RETURNING` and conditional updates, so they live in a JDBC repository, `AiStateRepository`.
4. **The "Never use" list** is `FoodRules.excludedTerms(allergens, diets)` (new; the plain terms of those rows and every row they reference, sorted, without exceptions) plus the dislikes. If it exceeds 150 terms, the terms are kept in full anyway: correctness beats prompt size.
5. **Conflict reasons** in a 400 are `"allergy: <label>"`, `"diet: <label>"` or `"dislike"`.
6. **Groq structured output:** use `response_format: {type: "json_schema", json_schema: {name: "recipe", strict: true, schema}}`. If the Groq docs say `openai/gpt-oss-120b` doesn't support it, use `{type: "json_object"}` and append the schema to the system text. Record which one in the ledger.
7. **Gemini request field names** (`systemInstruction`, `generationConfig.responseMimeType`, `responseJsonSchema`, `thinkingConfig.thinkingLevel`) are checked against the current docs before coding. Record any difference in the ledger.
8. **Quota detection:** HTTP 429 always means quota. Gemini also signals quota with `status: "RESOURCE_EXHAUSTED"` in the error body. Every other 4xx is `AiUnavailableException` (with the status in the message), because a bad request is our bug, not the user's.
9. **The local date for daily meals** must be within one day of the server's UTC date (`|date - todayUtc| <= 1`).
10. **No `Clock` bean.** Every class that needs time follows `MfaFactorLookup`: an `@Autowired` public constructor that passes `Clock.systemUTC()` (or a new `Random()`), and a package-private constructor that takes them, for tests.
11. **Rulings during the build** go in the ledger `.superpowers/sdd/2026-10-31-ai-recipe-generation/progress.md` (git-ignored).

## Review Focus

1. **The AI ignores the rules and puts a forbidden ingredient only in a step** ("serve with a dollop of cream"). The draft must be rejected for a dairy-free or milk-allergic user. Pinned in Task 5 (`SafetyCheckTest.allergenOnlyInStep_isRejected`).
2. **The provider returns prose, a fenced code block or truncated JSON** instead of the schema. It must count as a failed attempt (retry), never a 500. Pinned in Task 5 (`DraftParserTest`) and Task 8 (`malformedReply_retries`).
3. **Two tabs open the home page at the same moment.** Exactly one AI call is made; the other tab gets `generating` and then the same set. Pinned in Task 1 (`claim_secondCallReturnsFalse`) and Task 10.
4. **A user who types "Peanut butter" with a peanut allergy,** or "Tomatoes" when "tomato" is a dislike: rejected up front with the reason, and no generation is used up. Pinned in Task 8 (`conflict_isRejectedBeforeReserving`).
5. **An exception message or log line containing the API key,** for example from a provider error body echoing the request. Pinned in Task 3 (`keyNeverInExceptionMessage` for both providers).
